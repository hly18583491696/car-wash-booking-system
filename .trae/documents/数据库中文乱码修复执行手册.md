## 概述
- 目标：识别并修复 MySQL 数据库中所有中文乱码，统一为 `utf8mb4`，并保证应用端连接字符集一致。
- 覆盖对象：库 `carwash_db`，表 `users`、`services`、`bookings`、`system_config`、`feedback`、`time_slots` 等所有 varchar/text 中文字段。

## 执行前备份（必须）
- 在终端执行（Windows）：
  1) `chcp 65001`
  2) `mysqldump -u root -p123456 --default-character-set=utf8mb4 carwash_db > backup\carwash_db__before_fix.sql`
- 说明：备份完成后再进行任何字符集变更；发生异常时用该备份回滚。

## 步骤1：识别当前字符集
- 服务器与连接：
  - `SHOW VARIABLES LIKE 'character_set%';`
  - `SHOW VARIABLES LIKE 'collation%';`
  - 关注：`character_set_server`、`character_set_database`、`character_set_client`、`character_set_results`、`collation_server`
- 数据库与表：
  - `SELECT schema_name, default_character_set_name, default_collation_name FROM information_schema.SCHEMATA WHERE schema_name='carwash_db';`
  - `SELECT TABLE_NAME, TABLE_COLLATION FROM information_schema.TABLES WHERE TABLE_SCHEMA='carwash_db' ORDER BY TABLE_NAME;`
- 列级字符集：
  - `SHOW FULL COLUMNS FROM services;`（对重点表重复执行）

## 步骤2：检测乱码数据
- 常用检测（示例针对 services）：
  - `SELECT id, name FROM services WHERE name REGEXP '[ÃÂ]';`
  - `SELECT id, description FROM services WHERE description REGEXP '[ÃÂ]';`
- 十六进制辅助：
  - `SELECT id, HEX(name) AS hex_name FROM services WHERE name REGEXP '[ÃÂ]';`
- 其他表类似执行，逐列排查。

## 步骤3：统一库与表字符集为 utf8mb4（不改变文本内容）
- 统一数据库：
  - `ALTER DATABASE carwash_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
- 统一所有表（逐表执行）：
  - `ALTER TABLE users CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
  - `ALTER TABLE services CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
  - `ALTER TABLE bookings CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
  - `ALTER TABLE system_config CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
  - `ALTER TABLE feedback CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
  - `ALTER TABLE time_slots CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`

## 步骤4：修复已存在乱码（列为 latin1、数据为 UTF-8 的典型场景）
- 二段式修复（保留原始字节，避免二次转码）：
- 针对 services 表示例（根据实际长度调整）：
  1) 改为二进制临时类型（保留原始字节）：
     - `ALTER TABLE services MODIFY name VARBINARY(100);`
     - `ALTER TABLE services MODIFY description VARBINARY(1024);`
  2) 改回 UTF-8 文本类型（解释为正确的 UTF-8）：
     - `ALTER TABLE services MODIFY name VARCHAR(100) CHARACTER SET utf8mb4;`
     - `ALTER TABLE services MODIFY description TEXT CHARACTER SET utf8mb4;`
- 其他表的中文列（如 users.real_name、bookings.notes、system_config.config_value、feedback.content/reply）同样执行该二段式流程。

## 步骤5：修复已存在乱码（列为 latin1、数据也按 latin1 写入）
- 转换公式（先在样本行验证后批量执行）：
  - `UPDATE services SET name = CONVERT(CAST(CONVERT(name USING latin1) AS BINARY) USING utf8mb4) WHERE name REGEXP '[ÃÂ]';`
  - `UPDATE services SET description = CONVERT(CAST(CONVERT(description USING latin1) AS BINARY) USING utf8mb4) WHERE description REGEXP '[ÃÂ]';`
- 其他表的中文列按需套用同样语句。

## 步骤6：统一应用端连接字符集
- 后端连接（保持并审查）：
  - `spring.datasource.url=jdbc:mysql://localhost:3306/carwash_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai`
  - 驱动：`com.mysql.cj.jdbc.Driver`
- 前端与终端：
  - 浏览器默认 UTF-8；CLI 需 `chcp 65001` 避免代码页造成的误判（例如 PowerShell 显示 `æ…`）。

## 步骤7：验证
- SQL 验证：
  - `SELECT id, name, description FROM services ORDER BY id;` 所有中文应正常显示。
  - 其他表同理执行抽样 SELECT。
- 应用端验证：
  - 打开服务列表、支付页、订单页确认中文展示正常；同时用浏览器或 Postman 调用 REST 接口确认 JSON 字符串为可读中文。
