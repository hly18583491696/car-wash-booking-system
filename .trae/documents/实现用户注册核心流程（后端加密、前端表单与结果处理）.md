- 在 `backend/src/main/java/com/carwash/dto/RegisterRequest.java`：
  - 保留并强校验必填字段：`username`（格式校验，3–20，字母/数字/下划线）、`password`（复杂度校验，8–20，至少含字母与数字）、`confirmPassword`（非空）、`email`（邮箱格式）。
  - 将 `realName`、`phone`、`smsCode` 改为可选（移除 `@NotBlank` 与强校验），为后续拓展预留。

3. 注册业务逻辑只实现核心流程，暂缓验证码
- 在 `backend/src/main/java/com/carwash/service/impl/UserServiceImpl.java:69-114`：
  - 保留“密码与确认密码一致性校验”。
  - 移除或暂时跳过 `smsService.verifyCode(...)` 的验证码校验。
  - 用户名唯一性检查保留；`email` 唯一性仅在提供时检查；`phone` 唯一性仅在提供时检查。
  - 使用 `passwordEncoder.encode(request.getPassword())` 写入加密密码；持久化用户，角色 `user`，状态启用。
  - 按现有 `Result/BusinessException` 规范返回成功/失败。

4. 接口规格
- `POST /api/auth/register`（已存在，见 `backend/src/main/java/com/carwash/controller/AuthController.java:34-43`）
- 请求示例（核心字段）：
```json
{
  "username": "alice_001",
  "password": "Abcd1234!",
  "confirmPassword": "Abcd1234!",
  "email": "alice@example.com"
}
```
- 成功返回：`{ code: 200, message: "注册成功" }`
- 失败返回：`{ code: <错误码>, message: <原因> }`

5. 兼容性提示
- 切换到 BCrypt 后，历史“明文口令”账号将无法登录；新注册的账号按加密方案正常登录。若需兼容，后续可增加“平滑迁移”策略（非本次范围）。
