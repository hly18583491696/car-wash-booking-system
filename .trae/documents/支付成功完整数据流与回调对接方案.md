## 数据流总览
- 前端：第三方“span”支付库成功回调 → 组装回调数据 → 通过 HTTPS 调用后端支付回调 API
- 后端：校验签名 → 持久化支付结果（更新 `payments`/`bookings`）→ 返回订单状态
- 前端：根据后端成功响应更新本地状态（Vuex）并刷新页面数据，展示支付记录

## 前端改造
- 回调处理：在 `Payment.vue` 成功回调中收集字段：`paymentNo(out_trade_no)`、`transaction_id`、`order_no`、`amount`、`payment_method`、`paid_at`、`sign`、`timestamp`、`nonce_str`
- 安全传输：通过 `HTTPS` 向后端指定网关路径提交：`POST /api/payment/callback/{method}`（`method ∈ {wechat,alipay,virtual}`，控制器位于 `backend/src/main/java/com/carwash/controller/PaymentController.java:132,153,170`）
- 请求载荷：JSON `{ out_trade_no, transaction_id, sign, timestamp, nonce_str, order_no?, amount?, paid_at? }`
  - 说明：`order_no/amount/paid_at`用于前端与审计展示，后端以数据库记录为准不信任这些数值
- 状态同步：收到成功响应后，Vuex 更新：
  - `payments/fetchByOrderNo(orderNo)` 刷新支付记录列表
  - `bookings/fetchByOrderNo(orderNo)` 刷新订单支付状态与时间
  - 触发页面重新获取（支付记录页“支付记录”与订单详情页）
- 错误处理：
  - 网络/签名失败 → toast 提示与错误日志 `console.error`；保留重试按钮与“返回订单页”导航

## 后端对接
- 回调入口：使用现有控制器端点 `POST /api/payment/callback/{method}`（`PaymentController.java:132,153,170`），将 JSON 参数映射为 `Map<String,String>`
- 签名验证：调用 `PaymentServiceImpl.verifyPaymentCallback(...)`（`backend/src/main/java/com/carwash/service/impl/PaymentServiceImpl.java:358-380`）
  - 优先使用统一验签组件 `CallbackSignatureVerifier`；失败则网关兜底验证
- 成功处理：`PaymentServiceImpl.handlePaymentCallback(...)`（`:171-229`）
  - 持久化：更新 `payments.status=paid`、`transaction_id`、`paid_at`；更新对应 `bookings.payment_status=paid`、`payment_method`、`paid_at`
  - 审计：写入 `payment_audit`（事件 `CALLBACK_VERIFIED`、`CALLBACK_UPDATE`）
- 响应：返回包含订单状态与支付流水号的统一响应（`PaymentResponse`）
- 幂等与安全：
  - 若多次回调，重复更新为 `paid` 保持幂等（基于当前实现重复更新无副作用）；建议后续增加“已是 paid 则直接返回”的优化
  - 严格依靠签名验证与内部支付记录，不信任前端金额与订单数据

## 安全要求
- 生产环境全站 `HTTPS`（反向代理或网关层启用 TLS）
- 请求体与签名字段完整，后端仅以 `out_trade_no/paymentNo` 定位记录并核对签名
- 记录审计日志以支持问题追踪（已在 `PaymentServiceImpl.savePaymentAudit`）

## 前端状态同步细节
- Vuex/Pinia：
  - `commit('payments/setByOrder', data)` 或 `dispatch('payments/fetchByOrderNo', orderNo)`
  - `dispatch('bookings/fetchByOrderNo', orderNo)` 更新订单状态卡片
- 视图刷新：支付成功后路由跳转至“支付记录”页或在当前页触发数据重新拉取

## 错误处理与日志
- 前端：统一 `Axios` 拦截器记录错误（`request.js:90-92`），弹窗提示与重试
- 后端：`Slf4j` 日志在以下位置输出：
  - 创建支付：`PaymentServiceImpl.java:75,141`
  - 验签：`PaymentServiceImpl.java:359-379`
  - 回调更新：`PaymentServiceImpl.java:207-228`
  - 失败监控：`paymentMonitor.markFailure()`
