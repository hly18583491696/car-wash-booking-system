## 目标
- 全面识别并修复 MySQL 中的中文乱码，统一为 UTF-8（建议 utf8mb4）。
- 校验并统一应用端与数据库端的字符集设置，建立预防机制。

## 步骤一：备份数据（必须）
- Windows 终端执行：
  - `chcp 65001`
  - `mysqldump -u root -p123456 --default-character-set=utf8mb4 carwash_db > backup\carwash_db__before_fix.sql`
- 说明：备份文件路径可按需调整；确保备份成功以便回滚。

## 步骤二：识别当前字符集与表/列设置
- 服务器与连接：
  - `SHOW VARIABLES LIKE 'character_set%';`
  - `SHOW VARIABLES LIKE 'collation%';`
  - 关注：`character_set_server`、`character_set_database`、`character_set_client`、`character_set_results`、`collation_server`。
- 数据库与表：
  - `SELECT schema_name, default_character_set_name, default_collation_name FROM information_schema.SCHEMATA WHERE schema_name='carwash_db';`
  - `SELECT TABLE_NAME, TABLE_COLLATION FROM information_schema.TABLES WHERE TABLE_SCHEMA='carwash_db' ORDER BY TABLE_NAME;`
- 列级字符集：对重点表（如 `users`、`services`、`bookings`、`system_config`、`feedback`）执行：
  - `SHOW FULL COLUMNS FROM services;`（查看 `Collation` 与 `Type`）

## 步骤三：检测乱码数据
- 典型症状：显示为 "Ã"、"Â" 等前缀字符；或 PowerShell 输出为 `æä½æå`。
- 建议快速检测（示例针对 `services`）：
  - `SELECT id, name FROM services WHERE name REGEXP '[ÃÂ]';`
  - `SELECT id, description FROM services WHERE description REGEXP '[ÃÂ]';`
- 若 REGEXP 不足以覆盖，可用十六进制辅助：
  - `SELECT id, HEX(name) AS hex_name FROM services WHERE name REGEXP '[ÃÂ]';`

## 步骤四：统一字符集为 utf8mb4
- 若数据库/表非 utf8mb4，先统一库与表（不改变文本内容）：
  - `ALTER DATABASE carwash_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
  - 针对所有业务表：
    - `ALTER TABLE services CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
    - 其他表同理：`users`、`bookings`、`system_config`、`feedback`、`time_slots`...

## 步骤五：修复已存在乱码数据（保留原始字节）
- 场景 A：列为 latin1，但实际存的是 UTF-8 字节，显示成乱码（常见）。
  - 两段式修复（防止二次转码）：
    1) 先转为二进制保留字节
       - `ALTER TABLE services MODIFY name VARBINARY(100);`
       - `ALTER TABLE services MODIFY description VARBINARY(1024);`（长度按实际列长度）
    2) 再改回为 utf8mb4 并解释为 UTF-8
       - `ALTER TABLE services MODIFY name VARCHAR(100) CHARACTER SET utf8mb4;`
       - `ALTER TABLE services MODIFY description TEXT CHARACTER SET utf8mb4;`
- 场景 B：列为 latin1，数据也按 latin1 写入，但你希望显示为 UTF-8
  - 使用转换公式：
    - `UPDATE services SET name = CONVERT(CAST(CONVERT(name USING latin1) AS BINARY) USING utf8mb4) WHERE name REGEXP '[ÃÂ]';`
    - `UPDATE services SET description = CONVERT(CAST(CONVERT(description USING latin1) AS BINARY) USING utf8mb4) WHERE description REGEXP '[ÃÂ]';`
- 注意：先在少量样本行验证，再批量执行；整个操作置于事务中，备份到位。

## 步骤六：统一应用与连接字符集
- 后端连接：
  - JAR 启动脚本已设置：`useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai`（backend/start-backend.bat:15–17），保留即可。
  - Maven 运行时建议在 `application.yml`/`application.properties` 中显式声明：
    - `spring.datasource.url=jdbc:mysql://localhost:3306/carwash_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai`
    - `spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver`
- 前端：HTML/JS 默认 UTF-8；问题多出在终端显示（PowerShell 默认非 UTF-8）。
  - 在终端中使用 `chcp 65001` 或通过浏览器/应用进行验证。

## 步骤七：验证修复效果
- SQL 验证：
  - `SELECT name, description FROM services ORDER BY id;` 观察中文是否正常。
  - `SELECT * FROM users WHERE real_name REGEXP '[^\x00-\x7F]';` 检查中文列是否正常可读。
- 应用验证：
  - 刷新前端页面查看服务列表与支付页中文显示；并验证 REST JSON 响应（浏览器或 Postman，非 PowerShell）。

## 步骤八：记录与预防
- 记录执行的 SQL、影响的表与行数、备份位置与时间戳。
- 预防措施：
  - 所有新表与库默认设为 `utf8mb4`；统一后端连接参数。
  - 数据导入导出统一使用 `--default-character-set=utf8mb4`。
  - 终端/工具统一使用 UTF-8 视图，避免误判。

## 回滚方案
- 如出现异常，使用备份文件：
  - `mysql -u root -p123456 --default-character-set=utf8mb4 < backup\carwash_db__before_fix.sql`

## 说明
- 你的截图中 `services` 表大部分中文显示正常，说明表/库多为 UTF-8；如仍有个别字段显示异常，优先对该列做“两段式修复”。
- PowerShell 的 JSON 显示乱码通常是控制台代码页问题，不是数据库问题；用浏览器/前端页面验证最准确。
