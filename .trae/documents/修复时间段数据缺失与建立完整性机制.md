## 问题确认
- 使用后端接口检查当天时间段：`GET /api/time-slots/available?date=YYYY-MM-DD`（frontend/src/api/timeSlots.js:11-15）。
- 当前返回空数组，前端 `slots-grid` 为空（frontend/src/views/Appointment.vue:77-99）。
- 可能原因：数据库 `time_slots` 表无当天数据或数据被清空，初始化脚本未执行。

## 处理方案
### 步骤1：检查数据是否存在
- 通过命令行调用接口并打印结果：
  - PowerShell：`Invoke-WebRequest http://localhost:8080/api/time-slots/available?date=<today>`
- 若为空，则进入数据插入流程。

### 步骤2：重新插入当天数据（可靠来源）
- 使用已验证的初始化脚本 `sql/init.sql` 的插入模式为参考（sql/init.sql:202-218），但避免全量 TRUNCATE，按天增量插入：
- 通过 MySQL CLI 执行增量插入语句（仅当不存在该日期记录时）：
  - `INSERT INTO time_slots (date,start_time,end_time,max_bookings,current_bookings,status) VALUES (CURDATE(),'09:00:00','09:30:00',3,0,1), ...`（覆盖 09:00-18:00 每 30 分钟，总计14条）
  - 使用 `INSERT IGNORE` 或 `ON DUPLICATE KEY UPDATE` 防止重复（表有 `uk_date_time` 唯一键，sql/init.sql:74）。
- 全过程记录日志与错误处理：
  - 捕获 CLI 返回码，输出详细错误信息；成功时输出插入条数。

### 步骤3：验证前端显示
- 再次调用 `GET /api/time-slots/available?date=YYYY-MM-DD` 验证返回非空。
- 刷新前端页面 `http://localhost:3000/`，确认 `slots-grid` 出现时间段卡片并显示“x个空位/已满”。

### 步骤4：建立数据完整性机制（防复发）
- 后端新增定时任务（@Scheduled）每日校验与补全未来 N 天时间段：
  - 位置建议：`com.carwash.service.TimeSlotMaintenanceService`，依赖 `TimeSlotService`（backend/src/main/java/com/carwash/service/TimeSlotService.java:16-52）。
  - 逻辑：检查 `date` 的记录数是否满足配置（例如每天14个），不足则按营业时间生成并插入。
  - 日志：INFO 记录校验结果与补全数量，ERROR 记录异常堆栈。
- 新增调试接口（只读）：`GET /api/debug/time-slots/verify?date=YYYY-MM-DD` 返回当天时间段统计与缺失明细，便于人工诊断。

## 风险与注意
- 避免执行 `sql/init.sql` 的 TRUNCATE 段（init.sql:153-178）以免清空业务数据；仅做增量插入。
- 确保 MySQL 服务已启动，连接参数与账号匹配（reset脚本使用 `root/123456`）。
- 保留 `SecurityConfig` 白名单（backend/src/main/java/com/carwash/config/SecurityConfig.java:81），无需变更。

## 执行计划
- 获批后：
  1) 运行检查命令确认数据为空
  2) 执行增量插入当天时间段（带错误处理与日志输出）
  3) 重新验证接口与前端显示
  4) 提交后端定时校验与调试接口实现，确保数据长期完整
