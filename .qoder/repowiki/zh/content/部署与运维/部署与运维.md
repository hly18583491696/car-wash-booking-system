## 系统启动流程

本节详细说明通过 `start-services.bat` 脚本启动后端Spring Boot应用、前端Vite服务及Redis的完整流程。

### 启动脚本执行步骤

`start-services.bat` 脚本按照以下顺序自动执行系统组件的启动：

1. **检查MySQL服务状态**：脚本首先检查MySQL服务是否已运行，若未运行则尝试启动
2. **启动Redis服务**：检查6379端口是否被占用，若未占用则启动本地Redis服务
3. **启动后端服务**：进入backend目录，通过Maven命令 `mvn spring-boot:run` 启动Spring Boot应用
4. **启动前端服务**：进入frontend目录，通过 `npm run dev` 启动Vite开发服务器

### 系统访问地址

启动完成后，系统提供以下访问地址：

- **前端地址**：http://localhost:3000
- **后端地址**：http://localhost:8080
- **真实数据测试页**：http://localhost:3000/real-data-test

### 测试账号信息

系统预置了以下测试账号：

- **管理员**：admin / admin123
- **普通用户**：user001 / user123

## 服务重启操作

`restart-services.bat` 脚本用于标准的服务重启操作，确保系统在更新或异常后能够快速恢复正常运行。

### 重启流程

脚本执行三阶段重启流程：

1. **停止现有服务**：
   - 终止占用3003端口（前端）的进程
   - 终止占用8080端口（后端）的进程
   - 强制结束java.exe和node.exe相关进程

2. **等待端口释放**：
   - 暂停3秒，确保端口完全释放

3. **重新启动服务**：
   - 重新启动后端Spring Boot服务
   - 重新启动前端Vite服务

### 重启后访问信息

重启完成后，系统提供以下访问信息：

- **前端主页**：http://localhost:3003
- **数据同步测试**：http://localhost:3003/data-sync-test
- **后台管理**：http://localhost:3003/admin
- **后端API**：http://localhost:8080/api

脚本还会自动打开数据同步测试页面，便于快速验证系统状态。

## 数据库重置操作

数据库重置是系统维护中的重要操作，需谨慎使用。系统提供了两种重置脚本，具有不同的安全级别。

### 安全重置脚本（推荐）

`reset-database-safe.bat` 是推荐使用的安全重置脚本，具有以下特点：

- **数据备份**：执行重置前自动备份当前数据库
- **用户确认**：需要输入"YES"确认操作
- **详细日志**：提供完整的操作反馈和错误处理建议

#### 安全重置流程

1. **用户确认**：提示用户输入"YES"确认操作
2. **数据备份**：
   - 创建backup目录（如不存在）
   - 生成带时间戳的备份文件名
   - 使用mysqldump命令备份数据库
3. **执行重置**：执行SQL重置脚本，清空并重新初始化数据

备份文件存储在 `backup/` 目录下，文件名为 `carwash_db_backup_YYYYMMDD_HHMMSS.sql` 格式。

### 快速重置脚本

`reset-database.bat` 是快速重置脚本，特点如下：

- **快速执行**：无备份和确认步骤，直接执行重置
- **风险较高**：操作不可逆，无数据备份

## 运维常规操作

### 性能监控

参考《后台管理页面性能优化报告.md》中的建议，系统实现了多项性能优化措施：

#### 前端性能优化
- **路由跳转优化**：移除不必要的路由跳转，使用 `requestAnimationFrame` 优化UI更新时机
- **数据缓存机制**：实现5分钟有效期的数据缓存，减少重复请求
- **图表性能优化**：图表实例缓存和复用，禁用不必要的动画效果
- **计算属性优化**：添加计算结果缓存和防抖机制
- **事件处理优化**：对窗口resize等事件进行300ms防抖处理

#### 性能监控指标
- **标签切换响应时间**：从500-1000ms降低到50-100ms
- **图表初始化时间**：从300-600ms降低到100-200ms
- **数据加载时间**：缓存命中时从200-500ms降低到10-50ms

### 日志查看

系统配置了详细的日志记录，主要日志配置如下：

- **日志级别**：
  - `com.carwash` 包：debug级别
  - `org.springframework.security` 包：debug级别
- **日志格式**：包含时间、线程、日志级别、类名和消息

日志输出格式为：`yyyy-MM-dd HH:mm:ss [线程] 日志级别 类名 - 消息`

### 数据库备份

#### 自动备份
使用 `reset-database-safe.bat` 会自动创建备份：
- **备份位置**：`backup/` 目录
- **文件命名**：`carwash_db_backup_YYYYMMDD_HHMMSS.sql`
- **备份内容**：完整数据库结构和数据

#### 手动备份
```bash
# 创建完整备份
mysqldump -u root -p123456 carwash_db > backup/manual_backup.sql

# 恢复备份
mysql -u root -p123456 carwash_db < backup/manual_backup.sql
```

### Redis配置与管理

#### Redis连接配置
后端应用的Redis配置位于 `application.yml` 文件中：

```yaml
spring:
  redis:
    host: localhost
    port: 6379
    password: 
    database: 0
    timeout: 3000ms
```

#### Redis安装选项
1. **Windows原生安装**：从GitHub下载Redis for Windows版本
2. **Docker运行**：`docker run -d -p 6379:6379 --name redis-server redis`
3. **WSL安装**：在Windows子系统中安装Redis

#### 启动顺序建议
1. 启动数据库（MySQL）
2. 启动Redis服务
3. 启动后端服务
4. 启动前端服务
5. 启动MCP Server Redis

## 常见问题排查

### 数据库连接问题

#### 连接失败
```
ERROR 2003: Can't connect to MySQL server
```
**解决方案**：
- 检查MySQL服务是否启动
- 确认端口3306是否开放
- 验证连接参数是否正确

#### 权限不足
```
ERROR 1045: Access denied for user 'root'
```
**解决方案**：
- 检查用户名和密码
- 确认用户具有足够权限
- 尝试重新设置MySQL root密码

#### 数据库不存在
```
ERROR 1049: Unknown database 'carwash_db'
```
**解决方案**：
- 先创建数据库：`CREATE DATABASE carwash_db;`
- 或运行初始化脚本：`sql/init.sql`

### Redis连接问题

#### 服务未运行
```
[Redis Error] AggregateError [ECONNREFUSED]
```
**解决方案**：
- 检查Redis服务是否启动
- 使用 `redis-cli ping` 验证连接
- 确认6379端口未被占用

#### 配置问题
**检查项**：
- `bind 127.0.0.1` 配置是否正确
- 防火墙是否允许Redis端口通信
- 是否需要管理员权限运行

### 端口冲突

#### 检查端口占用
```cmd
# 检查8080端口
netstat -ano | findstr :8080

# 检查3000/3003端口
netstat -ano | findstr :3000
netstat -ano | findstr :3003

# 检查6379端口
netstat -ano | findstr :6379
```

#### 终止占用进程
```cmd
# 根据PID终止进程
taskkill /f /pid <PID>
```
